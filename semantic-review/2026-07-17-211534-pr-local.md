# Desktop deployment blockers in trust and persistence changes

The scoped changes move workspace authority into Main, add source-bound agent edits and durable runs, serialize preference/profile persistence, hydrate mandatory-update policy, and coordinate renderer modals. The approach is meant to keep renderer input non-authoritative and make sensitive transitions durable. Nine confirmed security or correctness blockers remain in those paths and directly connected call sites.

**Watch for:** **HIGH, confirmed** leaf symlink mutations operate on the referent; **HIGH, confirmed** a substituted recent-workspace symlink can authorize a different root; **HIGH, confirmed** persisted snapshots are readable without a current path capability; **HIGH, confirmed** approvals are keyed only by run and can be consumed before the matching preview; **MEDIUM, confirmed** Settings JSON writes leave Main runtime policy stale; **MEDIUM, confirmed** profile application can crash between its two commits; **MEDIUM, confirmed** profile consumers adopt the unsanitized request instead of the committed state; **MEDIUM, confirmed** failed mandatory-update hydration leaves the application unblocked; **MEDIUM, confirmed** clearing history during a run permanently detaches that run from its journal.

## High-level view

The path capability layer has three **HIGH, confirmed** boundary gaps: destructive methods dereference the selected symlink leaf, a stored recent can authorize a replacement symlink target, and snapshot reads do not consult the current capability set.

The agent consent boundary has a **HIGH, confirmed** identity gap because run ID becomes approvable before its preview is emitted. Run persistence has a separate **MEDIUM, confirmed** lifecycle gap: clearing history removes active entries and later events will not recreate them.

Preference adoption has three **MEDIUM, confirmed** inconsistencies. Settings JSON can commit policy without refreshing Main; a crash can split a profile’s settings and keybindings commits; and successful profile application leaves Main and renderer memory holding the pre-sanitized request rather than the committed values.

Mandatory-update hydration has a **MEDIUM, confirmed** fail-open path. If the initial snapshot rejects and no newer event arrives, the default non-blocking state remains active even when Main already requires an update.

1. **Leaf symlink referent mutation** — **HIGH, confirmed:** rename, move, and trash operate on the selected symlink’s canonical target. Authorize the parent and mutate the leaf without following it.
2. **Recent-root identity substitution** — **HIGH, confirmed:** reopening a stored lexical path can authorize a replacement symlink or junction target. Persist the approved canonical identity and require it to match at reopen time.
3. **Snapshot capability bypass** — **HIGH, confirmed:** persisted metadata and contents remain renderer-readable without a currently authorized workspace. Filter listing and gate content reads by the stored source path’s current capability.
4. **Approval preview identity gap** — **HIGH, confirmed:** a run can be approved before the matching preview is emitted, and stale responses can settle later prompts. Bind resolution to a per-preview request token that becomes active only after emission.
5. **Settings runtime adoption gap** — **MEDIUM, confirmed:** Settings JSON commits do not refresh Main’s egress/update policy. Centralize post-commit runtime adoption for every managed settings write.
6. **Split profile crash commit** — **MEDIUM, confirmed:** process loss between the settings and keybindings renames leaves a mixed profile. Use one authoritative object or a recoverable durable transaction.
7. **Pre-sanitized profile adoption** — **MEDIUM, confirmed:** Main and renderer adopt the requested settings while disk receives normalized settings. Return and adopt the committed normalized pair.
8. **Mandatory-update hydration fail-open** — **MEDIUM, confirmed:** a rejected initial snapshot leaves the default non-blocking state in force. Keep hydration unresolved and blocking until an authoritative snapshot is obtained or recovery is required.
9. **Active-run journal erasure** — **MEDIUM, confirmed:** clearing history deletes active entries and later events cannot restore them. Reject clear during active runs or clear only terminal records.

## Leaf symlinks redirect destructive filesystem operations

**HIGH, confirmed.** `assertAuthorizedPath` resolves and returns the complete path through `fs.realpath` (`apps/desktop/src/main/services/pathAuthorization.ts:31-40`); rename, move, and trash then mutate that returned path (`apps/desktop/src/main/services/filesystem.ts:155-162`, `:169-189`, `:196-202`). Selecting an in-workspace symlink therefore mutates its target and leaves the link behind. An outside-pointing link is denied entirely, so the API cannot remove the link itself.

Authorize the canonical parent while preserving and `lstat`-checking the requested leaf, then mutate the leaf without following it. Cover links to both inside and outside targets with destructive-operation regressions.

## A stored recent can authorize a substituted workspace root

**HIGH, confirmed.** Recent provenance is checked with a lexical path comparison (`apps/desktop/src/main/services/recents.ts:47-48`), after which the dialog service authorizes that path (`apps/desktop/src/main/services/dialog.ts:35-39`). `authorizeWorkspaceRoot` resolves whatever now occupies it and records the resulting target (`apps/desktop/src/main/services/pathAuthorization.ts:65-70`). Replacing a recorded directory with a symlink or junction lets the unchanged recent path grant authority over a different directory, including one outside the originally approved root.

Persist the approved canonical identity and require the reopen-time `realpath` identity to match it. A changed or unverifiable identity should require a new trusted chooser interaction.

## Snapshot persistence bypasses the current capability set

**HIGH, confirmed.** Listing returns every indexed checkpoint (`apps/desktop/src/main/services/snapshots.ts:242-243`), while content retrieval reads an object by entry ID without `assertAuthorizedPath` (`apps/desktop/src/main/services/snapshots.ts:247-252`). IPC exposes both calls (`apps/desktop/src/main/ipc.ts:1516`, `:1523-1524`). After restart with no authorized workspace, renderer code can still enumerate historical paths and retrieve snapshotted contents.

Filter listing by current authorization and reject content requests whose stored source path is unauthorized, using missing-path semantics where snapshots outlive source files. A restart regression should prove metadata and content remain inaccessible until the corresponding root is authorized.

## Run-scoped approval is not bound to the emitted preview

**HIGH, confirmed.** A pending approval keyed only by run ID is installed before asynchronous preview preparation (`apps/desktop/src/main/services/agent.ts:1174-1176`); the approval event is emitted later (`apps/desktop/src/main/services/agent.ts:1211-1215`). Resolution and IPC require only run ID plus a boolean (`apps/desktop/src/main/services/agent.ts:1261-1262`; `apps/desktop/src/main/ipc.ts:1059-1061`). An early response can approve before the preview exists, and a delayed response to one prompt can settle a later prompt in the same run.

Assign each preview an approval-request token, emit it with the preview, and require it for resolution. Make the request resolvable only after emission, invalidate that exact token on cancellation, and reject early, stale, duplicate, and post-cancellation responses.

## Managed Settings JSON commits do not update Main runtime policy

**MEDIUM, confirmed.** Managed settings-file writes route through `writeResolvedSettingsFile` (`apps/desktop/src/main/services/filesystem.ts:72-75`) and persist sanitized settings (`apps/desktop/src/main/services/settings.ts:134-154`), but generic filesystem IPC returns without `applyRuntimeSettings` (`apps/desktop/src/main/ipc.ts:557-559`). Dedicated settings IPC does apply the commit (`apps/desktop/src/main/ipc.ts:607-611`), updating egress safety and update configuration (`apps/desktop/src/main/ipc.ts:333-341`). A Settings JSON edit to `ai.safety.*` or update policy can therefore reach disk while Main keeps enforcing the old policy until another adoption path or restart.

Centralize runtime adoption after every settings commit, or return the normalized commit to every caller and require adoption. Assert identical runtime policy after equivalent UI and Settings JSON writes.

## Profile application is not crash-atomic

**MEDIUM, confirmed.** Profile application commits settings and keybindings with two independent renames (`apps/desktop/src/main/services/profilePreferences.ts:79-82`). In-process rollback does not cover process or power loss between them, which leaves a permanently mixed profile.

Store the pair in one authoritative object or add a durable transaction record with startup recovery. Fault-injection should prove every interruption recovers either the complete old pair or complete new pair.

## Profile consumers adopt the pre-sanitized request

**MEDIUM, confirmed.** The profile service creates `normalizedSettings` by sanitizing custom headers (`apps/desktop/src/main/services/profilePreferences.ts:61-65`) but returns `Promise<void>` (`apps/desktop/src/main/services/profilePreferences.ts:57-60`). Main applies the original request (`apps/desktop/src/main/ipc.ts:651-652`), and `ProfilesView` stores the original `nextSettings` (`apps/desktop/src/renderer/src/workbench/ProfilesView.tsx:170-172`). Rejected headers therefore remain in memory while disk contains the sanitized form, leaving subsequent consumers on values Main refused to persist until restart.

Return normalized committed settings and keybindings over IPC; use that response for Main runtime adoption and both renderer stores. Compare disk, Main, and renderer state immediately after applying a profile containing rejected headers.

## Mandatory-update hydration fails open on snapshot rejection

**MEDIUM, confirmed.** Update state defaults to `mustBlock: false` (`apps/desktop/src/common/updateState.ts:43-52`). If `getState()` rejects, `UpdateView` applies only buffered live events and neither retries nor enters a blocking hydration state (`apps/desktop/src/renderer/src/workbench/UpdateView.tsx:71-78`). If Main was already in mandatory mode and emits no newer event, the renderer remains unblocked.

Represent unresolved hydration explicitly and fail closed, then retry the authoritative snapshot or show a blocking recovery error. Test rejection after Main enters mandatory mode with no subsequent event.

## Clearing history erases active-run durability

**MEDIUM, confirmed.** Clear replaces the whole run map with an empty map (`apps/desktop/src/main/services/agentRuns.ts:211-214`), and later events for a missing ID return without recreating it (`apps/desktop/src/main/services/agentRuns.ts:128-130`). IPC exposes clear (`apps/desktop/src/main/ipc.ts:1067`), while the task view does not disable it for active runs (`apps/desktop/src/renderer/src/workbench/TasksView.tsx:568-571`). Clearing during execution permanently removes that run’s durable history and eventual terminal state.

Reject clear while a run is nonterminal, or remove only terminal entries. Test clear during execution followed by more events and restart recovery.
