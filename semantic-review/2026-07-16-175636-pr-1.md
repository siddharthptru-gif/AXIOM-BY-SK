## High-level view

Request ownership now starts before asynchronous setup: Chat preallocates stream IDs and Main retains tombstones, while Agent installs its ID/listener before Main preflight and Main converts cancellation-raced final events. Composer captures the compose/refine workspace and refuses later refine/apply from another workspace. Editor actions remain queued until Chat acknowledges them, and ChatHistory defers unmount focus restoration and targets a surviving thread after deletion.

Safe Edit’s new serialization and stale checks remain fail-open when a file cannot be read, because read failures are represented as absence in both validation and snapshotting. Its rollback path also suppresses restoration errors, so a partially committed batch can look like an ordinary failed apply.

Conversation operations are serialized and corrupt top-level stores are quarantined, but upsert replacement is keyed globally by conversation ID rather than by scope plus ID. This permits one opaque scope to remove another scope’s same-ID record despite the scope-local API.

The shared credential-header classifier misses compact bare-auth names. Separately, the normal streaming route dispatches `chatWithFailover()` attempts without the final AI-service guard used by `chat()`.

Cache keys bind Main-only credentials and safe headers, but lowercasing the complete base URL merges endpoints whose case-sensitive paths differ.

<summary>Details</summary>

### Unreadable files become overwriteable, unsnapshotted creates

**HIGH — confirmed.** `currentState()` in `main/services/safeEdit.ts` catches every `fs.readFile` failure and returns `{ exists: false, hash: '' }`; `readCurrent()` in `main/services/snapshots.ts` likewise returns `null`. Composer review metadata also treats any file-read failure as a nonexistent target. None distinguishes `ENOENT` from `EACCES`, sharing violations, or transient I/O failures.

With an existing unreadable target whose parent directory remains writable, Composer records a create, Main validates an “absent” file, and capture records that no original existed. Rename can replace the target; if a later edit fails, restoration deletes the replacement instead of restoring the original. Repeated stale checks do not help because each repeats the same fail-open read.

Treat only `ENOENT` as missing and reject the batch on every other read failure. A checkpoint should become usable only after every target was positively read or positively proven absent.

### Restore failures are hidden behind a successful rollback audit

**MEDIUM — confirmed.** Safe Edit calls `restoreCheckpoint(checkpoint.runId).catch(() => undefined)`, then audits “Rolled back a batch” and returns only the original write error with `applied: []`. `restoreCheckpoint()` stops at its first failed entry, so neither result nor audit identifies files left modified.

If the first file commits, a later commit fails, and restoration then hits a lock, permission error, missing object, or concurrent snapshot clear, the caller sees an ordinary failed apply while the working tree retains part of the batch. Rollback should attempt every entry, collect unresolved paths, and surface a distinct rollback-failed result; success must be audited only after all entries restore.

### Scope-local upsert removes a matching ID from every scope

**MEDIUM — confirmed.** `mutateConversations()` scopes delete and clear, but upsert uses `current.filter(candidate => candidate.id !== conversation.id)`. A renderer can upsert in scope A using an ID held by scope B and remove B’s thread on the atomic write. The same loss can follow explicit legacy migration when imported data reuses an existing scoped ID and either copy is later renamed, pinned, or updated.

Filter out the prior record only when both `candidate.scopeId === mutation.scopeId` and IDs match. Seed same-ID records in two scopes in regression coverage and verify every mutation preserves the unrelated record.

### Compact bare-auth headers bypass the credential policy

**MEDIUM — confirmed.** The shared classifier catches `XApiKey`, `XAuthToken`, authorization, cookie, credential, and secret variants, but does not include compact names ending in `auth` or `authentication`; the current predicate returns false for `XAuth` and `XAuthentication`.

A custom provider can save `{"XAuth":"Bearer …"}` as ordinary settings. `CustomProviderForm`, settings migration, `toHeaderMap()`, and `trustedProviderHeaders()` all accept it, after which the adapter sends it as a normal header. Extend normalized detection to bare compact/delimited auth forms and exercise the same cases at UI, persistence, IPC, and outbound boundaries.

### Streaming failover skips the final AI-service header guard

**MEDIUM — confirmed.** `chat()` rebuilds trusted parameters through `trustedProviderHeaders()`, but `chatWithFailover()` passes each attempt directly to `dispatchByFamily()`, whose adapters spread `params.headers` into outbound requests. A direct internal failover call carrying `Authorization` or `XApiKey` therefore reaches dispatch without rejection. Current renderer chat first passes Main IPC coercion, but the requested unavoidable final boundary is absent from the production streaming route.

Reject headers inside `dispatchByFamily()` or sanitize every failover attempt so all current and future Main callers share one final guard. Direct tests should cover both `chat()` and `chatWithFailover()`.

### Cache normalization merges case-sensitive endpoint paths

**MEDIUM — confirmed.** `normalizeBaseForKey()` calls `.toLowerCase()` on the complete URL. Scheme and host are case-insensitive, but path and query components need not be; `/TenantA/v1` and `/tenanta/v1` can identify different deployments while producing one namespace.

With the same provider, model, Main-held key (or keyless endpoint), headers, and prompt, the first path can populate the cache and the second receive that response without egress. Parse and normalize only scheme, host, default port, and trailing-slash policy while preserving path/query case; verify host-case deduplication and path-case separation.
