# Task 1 lifecycle and trust-boundary re-review (v3)

The six previous findings are closed: only `ENOENT` denotes absence; `restoreCheckpoint()` attempts every requested entry and incomplete recovery is surfaced/audited; upsert matches scope plus ID; compact `XAuth`/`XAuthentication` names are credential headers; `dispatchByFamily()` owns the final header gate; and cache normalization preserves path/query case. Chat/Agent preflight cancellation, the editor-action queue, ChatHistory focus, and scoped history/migration show no additional confirmed HIGH/MEDIUM regression. Four blocking data-integrity and trust-boundary gaps remain.

**Watch for:** **HIGH — confirmed:** a renderer can make Main send a stored BYOK key to an arbitrary HTTPS endpoint; **HIGH — confirmed:** production Safe Edit callers can modify files without a base hash; **HIGH — confirmed:** rollback overwrites concurrent changes on targets Safe Edit never committed; **MEDIUM — confirmed:** concurrent snapshot captures can discard each other and delete referenced objects.

**Verdict**: NEEDS_CHANGES

## High-level view

**HIGH — confirmed.** AI IPC callers choose both provider ID and base URL; Main resolves the stored key from only the provider ID and sends it to that URL. The renderer can therefore redirect a key without reading it through IPC.

**HIGH — confirmed.** Composer supplies hashes, but Safe Edit does not require them. Chat code-block writes and checkpoint review submit hashless modifications, allowing content built from one version to overwrite a newer version.

**HIGH — confirmed.** Safe Edit requests restoration of the whole checkpoint rather than only entries it committed. A concurrent edit that triggers the per-file stale check is then replaced by the older snapshot and recorded as a successful rollback.

**MEDIUM — confirmed.** Snapshot index updates are atomic writes but not serialized transactions. Concurrent captures can both return success while one index update drops the other and garbage collection removes required content.

<summary>Details</summary>

### Main-held BYOK keys can be redirected without being read

**HIGH — confirmed.** `main/ipc.ts` accepts renderer-supplied `provider` and `baseUrl` in Chat, Agent, Review, and Composer, then calls `getSecret(aiSecretKey(provider))`. `resolveAiCreds()` also reuses the stored Custom key when a probe submits an empty key. `main/services/ai.ts` adds the key to `Authorization`, `x-api-key`, or Gemini's query string, while `guardedFetch()` permits any HTTPS destination.

After an OpenAI key is stored, renderer code can invoke Chat with `provider: "openai"` and an attacker-controlled HTTPS `baseUrl`; Main decrypts and sends the key to that host. The normal Custom-provider UI reaches the same boundary when its URL changes and Test Connection reuses the blank-field stored key.

Bind credentials to an endpoint identity when entered. Main should resolve built-in/default or explicitly approved proxy origins, and refuse to reuse a Custom key after its normalized endpoint changes until the user re-authorizes it.

### Safe Edit stale protection is optional for production callers

**HIGH — confirmed.** `common/safeEdit.ts` treats missing `baseHash` as no stale constraint. `ChatPanel.tsx` reads a code-block target only to choose create versus modify; `CheckpointsView.tsx` builds a hunk result from `data.cur`; both submit hashless modifications.

Open a checkpoint review at H0, let the editor write H1, then apply the reviewed hunks. Main validates only existence, snapshots H1, replaces it with content reconstructed from H0, and returns success. The Chat code-block action has the same read-to-apply window.

Require a non-empty `baseHash` for modify/delete in the shared type and Main validation, then compute it alongside each caller's source read.

### Whole-checkpoint rollback destroys the change that triggered stale rejection

**HIGH — confirmed.** `main/services/safeEdit.ts` checks all targets after capture and each target before commit. On a later failure it calls `restoreCheckpoint(runId)`, which correctly attempts every requested entry—but Safe Edit requests the entire checkpoint instead of paths in `applied`.

For a two-file batch, snapshot A and B at H0, commit A, then let an editor change B to H1 before B's per-file check. B is rejected as stale, but rollback writes B's H0 snapshot over H1 even though Safe Edit never changed B. Restore succeeds, so the caller gets `applied: []` and the audit records successful rollback while H1 is lost.

Request restoration only for committed paths. Before restoring one, verify its current state still matches what Safe Edit committed; otherwise surface it as unresolved recovery rather than overwrite a later external change.

### Snapshot captures race despite atomic index renames

**MEDIUM — confirmed.** `captureFiles()` reads the complete index, appends in memory, replaces the complete index, then garbage-collects without a shared mutation queue. Safe Edit, manual Checkpoints capture, and inline-edit capture can invoke it concurrently.

If A and B both read index I, they can publish I+A and I+B in turn. Both return success, but the later replacement loses one checkpoint; interleaved GC can delete A's or B's object before the surviving index is usable. A successful Safe Edit can report a run ID whose recovery data has disappeared.

Serialize capture, prune/GC, clear, and other index/object mutations. Keep Safe Edit's checkpoint leased against clear/GC until commit or rollback finishes.
