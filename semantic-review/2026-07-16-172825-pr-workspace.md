# Task 1 AI safety and persistence gaps

The implementation now carries cancellation IDs across renderer and Main, issues opaque conversation scopes, and attaches workspace/hash metadata to Composer reviews. Six HIGH/MEDIUM gaps remain at workspace, persistence, and credential boundaries: a review can move between roots, stale edits can pass before commit, credential headers can bypass the shared classifier, and conversation writes can lose unrelated data. Main’s response cache also remains broader than the BYOK identity that produced an answer.

**Watch for:** **HIGH · confirmed** Composer refinement can rebind a review from workspace A to B; **HIGH · confirmed** Safe Edit can overwrite a change made after hash validation; **HIGH · confirmed** compact names such as `XAuthToken` bypass persistence and Main egress rejection.

## High-level view

**HIGH · confirmed.** Direct Composer apply is root-checked, but refinement captures the currently open root and replaces `reviewRoot`. Refining an A review while B is open makes the resulting plan applicable to B.

**HIGH · confirmed.** Safe Edit validates all base hashes, awaits snapshot capture, and then mutates files without another validation or a batch lock. A disk change during that gap is silently overwritten.

**HIGH · confirmed.** Settings persistence and Main IPC share a delimiter-dependent header classifier. Compact credential names such as `XApiKey` and `XAuthToken` survive settings migration and are merged into provider requests.

**HIGH · confirmed.** Conversation scope identity includes root, endpoint, headers, routing/fallbacks, and secret revisions, but persistence still replaces one global list. Racing writes, a global 200-record cap, and treating every read failure as an empty store can erase newer, unrelated, or legacy records.

**MEDIUM · confirmed.** Agent, Composer, Review, completion, inline, and commit-message calls share a response cache that omits credential and custom-header identity. An exact request repeated after a key or tenant change can replay the prior identity’s answer without contacting the new identity.

<details>
<summary>Issues (6)</summary>

1. **HIGH · confirmed — Cross-root Composer refinement** — Refining an existing review after switching workspaces rebinds it to the new root and permits apply there. Reject refinement when `ws.rootPath !== reviewRoot`, or keep every refinement on the immutable originating root.
2. **HIGH · confirmed — Stale-hash commit gap** — Safe Edit releases the validated file state while snapshotting, then writes without revalidation. Serialize batches and revalidate every target immediately before the mutation phase.
3. **HIGH · confirmed — Compact credential-header bypass** — `XApiKey`/`XAuthToken` evade the shared classifier, remain in settings, and reach outbound requests. Canonicalize compact/vendor-prefixed names and independently reject them at provider-request construction.
4. **HIGH · confirmed — Unserialized full-list conversation writes** — Out-of-order atomic renames can make an older whole-store snapshot overwrite a newer mutation or another scope. Move scoped upsert/delete/migrate operations into a serialized Main-side store.
5. **HIGH · confirmed — Destructive conversation fallback and retention** — Read failures become `[]`, and a global `slice(0, 200)` silently drops unrelated or unmigrated records. Distinguish `ENOENT` from load failure, preserve/quarantine bad data, and make retention scope-aware.
6. **MEDIUM · confirmed — Cross-credential response cache** — The cache namespace excludes API-key revision and custom headers. Add an opaque Main-derived credential revision and normalized safe-header digest without exposing key bytes.

## Composer refinement can change the review’s workspace identity

**HIGH · confirmed** — `apps/desktop/src/renderer/src/workbench/ComposerPanel.tsx:114-176,196-201,229-245`.

Generate a review in workspace A for `src/auth.ts`, switch to B, and direct Apply is blocked. Refine remains enabled; it sends A’s original request/path plan with B’s context, reads returned edits against B, and stores B as the new `reviewRoot`. Apply then writes B. Refinement must remain bound to A or be refused and cleared after a root change.

## Stale hashes are released before the Safe Edit commit

**HIGH · confirmed** — `apps/desktop/src/main/services/safeEdit.ts:27-75`; hashes originate at `apps/desktop/src/renderer/src/workbench/ComposerPanel.tsx:154-176,258-280`.

A reviewed file at H0 passes `stageEdits`. While `captureFiles` is awaiting I/O, an editor, formatter, or external process writes H1; the service then commits the H0-based proposal and reports success. If H1 arrived before capture, the snapshot may preserve H1, but stale rejection has still failed and the concurrent edit is overwritten. Hold serialized batch admission and perform a final all-target hash/existence check immediately before mutation.

## Compact credential header names bypass every shared gate

**HIGH · confirmed** — `apps/desktop/src/common/headerSafety.ts:6-38`, `apps/desktop/src/main/services/settings.ts:16-18,65-66`, `apps/desktop/src/main/ipc.ts:252-260`, and `apps/desktop/src/main/services/ai.ts:40-45,398-400,485-488,548-551`.

The regex only recognizes a credential term at the start or after `-`/`_`. `Authorization`, `X-API-Key`, and `X-Auth-Token` are rejected, but `XApiKey` and `XAuthToken` are accepted. Entering `{"XAuthToken":"secret"}` therefore passes the form, survives trusted user/workspace settings writes, passes Main’s `toHeaderMap`, and is spread into the provider request. Canonicalize compact/camel-case vendor forms, add key/token/cookie/authorization regression cases, and retain an independent reject at the final Main request builder.

## Full-list conversation writes can overwrite newer or unrelated scopes

**HIGH · confirmed** — `apps/desktop/src/preload/index.ts:338-340`, `apps/desktop/src/main/ipc.ts:1330-1333`, `apps/desktop/src/renderer/src/workbench/ChatPanel.tsx:359,430-494`, and `apps/desktop/src/main/services/aiConversations.ts:69-85`.

Each renderer mutation merges its active scope into a cached all-scope snapshot and fire-and-forgets a complete replacement. A rename can enqueue W1 and a later delete W2; if W2 renames first and W1 finishes last, the deletion is undone. Two windows or a quick scope switch can similarly replace a newer B record with A’s stale B copy. Atomic temp-file rename protects syntax, not ordering; Main needs serialized, scope-specific mutations.

## Conversation load and retention can silently delete records

**HIGH · confirmed** — `apps/desktop/src/main/services/aiConversations.ts:52-85`.

`readConversations` maps `ENOENT`, malformed JSON, permission errors, and transient I/O failures to the same `[]`. Sending a message after a failed load makes the next full-list write replace the prior file with only the new conversation. Separately, with 200 B-scope or legacy records present, prepending the first A conversation and applying `slice(0, 200)` silently drops the last unrelated record. Return typed load failures, preserve or quarantine unreadable data, reject writes based on failed/stale reads, and apply retention per scope or through an explicit policy.

## AI response cache ignores BYOK and custom-header identity

**MEDIUM · confirmed** — `apps/desktop/src/main/services/aiGateway.ts:167-180`, `apps/desktop/src/main/services/ai.ts:603-613`, and `apps/desktop/src/main/services/{agent,completion,composer,gitAi,inlineChat,inlineEdit,review}.ts`.

Run the same Agent or Composer request with credential A or `X-Tenant: A`, then switch to B without changing endpoint, model, or messages. The process-global cache returns A’s text and usage before provider dispatch, so B is never contacted. Namespace entries with a Main-only credential revision and normalized safe-header digest rather than raw secret material.
