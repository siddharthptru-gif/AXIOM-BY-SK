=========================================
Architecture
=========================================

The implementation must follow Electron security best practices.

Renderer Process:
- UI only
- Never access Client Secret
- Never perform OAuth token exchange
- Never access GitHub credentials directly

Electron Main Process:
- Start and stop temporary localhost server
- Handle complete OAuth flow
- Exchange authorization code for access token
- Store credentials securely
- Perform GitHub API requests
- Perform Git operations

Use Electron IPC for communication.

=========================================
GitHub Login Flow
=========================================

When user clicks:

Connect GitHub

Automatically:

1. Start temporary localhost server.

2. Open default browser.

3. Navigate to GitHub OAuth authorization page using the supplied Client ID.

4. Wait for GitHub callback.

5. Capture authorization code.

6. Exchange authorization code using the supplied Client Secret.

7. Receive GitHub access token.

8. Validate token.

9. Fetch authenticated user.

10. Store token securely.

11. Stop localhost server.

12. Update UI.

Show:

- Avatar
- Username
- Connected account

=========================================
Secure Storage
=========================================

Use keytar.

Never store tokens inside:

- JSON
- Local Storage
- Session Storage
- Plain Text Files
- SQLite without encryption

=========================================
Disconnect
=========================================

Implement:

Disconnect GitHub

This must:

- Delete stored token
- Remove cached account
- Refresh UI
