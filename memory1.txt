7. HOW validate-real-extensions.cjs WORKS (understand this BEFORE editing it)
================================================================================
- PROBES = [groupName, [memberName, ...]]. Each member is searched in the extension's
  bundled JS with a plain text.includes(). probeBundle() returns { used, groups }.
- main() then calls compat.assessExtension(probe.used).
  *** THEREFORE: every probe member name flows into classifyApi(). A probe member that is
  NOT in API_SUPPORT falls through to the conservative default and makes the whole
  extension read "Not compatible". ALWAYS add the API_SUPPORT entry FIRST, and only probe
  for names the table classifies. ***
- SHIM_PROBES = group -> regex over src/main/extensionHostWorker.ts, giving shimStatus:
  implemented / not implemented / unclassified.
  Anchor these on a DISPATCH OP or a request() call, NOT on an identifier - a registration
  name may already have existed in an earlier phase and would pass falsely.
  Examples that are in place:
    ['workspaceSymbols', /'workspaceSymbol:resolve': \(provider, payload, token\) =>/]
    ['callHierarchy',    /'callHierarchy:incoming': \(provider, payload, token\) =>/]
    ['typeHierarchy',    /'typeHierarchy:supertypes': \(provider, payload, token\) =>/]
    ['inlineValues',     /'inlineValue:provide': \(provider, payload, token, document\) =>/]
    ['providerEvents',   /void request\('languages\.providerChanged', \{ handle \}\)/]
- DELIVERED_API_GROUPS is the REGRESSION GATE: any group listed there whose shimStatus is
  not 'implemented' sets process.exitCode = 1. 21 groups are listed today.
- Report artifact: %TEMP%\axiom-ext\real-extension-report.json

9. THE COMPAT TABLE RULE (highest-value lesson - do not forget this)
================================================================================
src/common/vscodeCompat.ts holds API_SUPPORT: Record<string, 'supported'|'partial'|
'unsupported'>, plus classifyApi() and assessExtension().

*** EVERY PHASE MUST UPDATE API_SUPPORT, OR COMPATIBILITY VERDICTS GO STALE AND REAL,
    WORKING EXTENSIONS READ "Not compatible". ***
This already happened for real: the Phase 7 §1-§4 value types (Task, ShellExecution,
ProcessExecution, CustomExecution, ShellQuoting, TaskGroup/Scope/RevealKind/PanelKind,
TerminalLocation/ExitReason/Profile, EnvironmentVariableMutatorType, the four DebugAdapter*
descriptors, DebugConsoleMode, DebugConfigurationProviderTriggerKind, FileChangeType) were
exported by the shim but MISSING from the table. Result: anthropic.claude-code read
"not compatible 0.95" and usernamehw.errorlens read "not compatible 0.80" even though every
API they use is shimmed. Fixed 2026-07-30; both now read compatible 1.00.

How classifyApi works (in order): exact key -> bare member name (API_SUPPORT_BY_MEMBER,
built once at load, skipping GENERIC_MEMBER_NAMES = get/store/delete/onDidChange/match/
dispose/copy/rename) -> namespace heuristic -> 'unsupported' (conservative default).
WHY bare-member lookup exists: a probe over MINIFIED bundled code recovers
`createWebviewPanel`, not `window.createWebviewPanel`, and `new vscode.WorkspaceEdit()` as
just `WorkspaceEdit`. So value-type CLASS NAMES need their own entries too.
Namespace heuristics today: notebooks/scm/tests/lm/chat -> unsupported; debug -> unsupported
(only the curated members ship); tasks -> unsupported (same); languages -> unsupported (only
the curated registrations ship); window.show* -> supported; authentication/secrets/commands
-> supported; workspace -> partial; unknown -> unsupported.

Pin every new claim in validate-extension-platform.cjs so the table can never drift ahead of
the shim. The existing pattern (C-15..C-17):
  C-15   compat.classifyApi(name) === 'supported' for each new value type
  C-15b  new RegExp(`\\n {2}${name},`).test(shim)   <- the name really is exported by
         src/main/extensionHostWorker.ts's `vscode` object
  C-16   every Object.values(PROVIDER_CHANGE_EVENTS) classifies 'supported'
  C-16b  classifyApi('onDidChange') === 'unsupported' AND
         classifyApi('onDidChangeBreakpoints') === 'partial'
  C-17   classifyApi('resolveWorkspaceSymbol') === 'supported' AND
         shim.includes("'workspaceSymbol:resolve'")

NOTE (open item, Phase 244 scope): vscodeCompat.ts has NO importer under src/ - verified by
search. It feeds the validators and the JSON compatibility report, not the UI. The Extensions
UI (renderer/src/workbench/ExtensionDetailPanel.tsx) shows ENGINE-RANGE compatibility from
